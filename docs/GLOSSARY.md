# Glossary

Every project term in one line of plain English. New terms are added in the stage that first uses them.

## The game and the console

| Term | Meaning |
| --- | --- |
| Atari 2600 | Atari's 1977 home games console. This Pac-Man (1982) was written for it. |
| ROM | The game's program and pictures as stored on the cartridge chip; here a 4096-byte file. |
| `.a26` | The usual file extension for an Atari 2600 ROM file. |
| Cartridge / CX2646 | The plug-in game module; CX2646 is Atari's catalogue number for Pac-Man. |
| 6502 (6507) | The processor inside the 2600; it runs the ROM's instructions one by one. |
| Bank switching | A trick bigger cartridges use to fit more than 4 KB; this ROM doesn't need it. |
| Vectors | Fixed addresses at the end of the ROM that tell the processor where to start (here $F000). |
| `$F000` | A memory address written in hexadecimal (base 16), the usual notation for 6502 addresses. |
| TIA | The 2600's video and sound chip. |
| Beam racing | The 2600 has no picture memory, so the program must feed the TV picture line by line while the beam draws it. |
| Sprite (GRP0/GRP1) | A small movable picture, such as Pac-Man or a ghost; GRP0/GRP1 are the TIA settings that hold their shapes. |
| Flicker | Ghosts drawn on alternate frames because the 2600 can't show them all at once; part of the original look. |

## Fingerprints and safety

| Term | Meaning |
| --- | --- |
| Fingerprint / hash | A short code calculated from a file; any change to the file changes it. Used to prove the ROM is untouched. |
| SHA-1, SHA-256, MD5, CRC32 | Four common kinds of fingerprint; the project's main one is SHA-1. |
| No-Intro | A catalogue of verified original game files, used to confirm our ROM is a clean original. |
| Read-only flag | A Windows setting that makes a file refuse changes; set on the original ROM in B4. |
| Working copy | A copy of the ROM (`rom\pacman.a26`) used for analysis so the original is never touched. |
| Checkpoint zip | A full copy of the project in a zip file outside the project folder, made at the end of each phase. |
| Restore test | Unpacking a backup into a fresh folder and proving it is complete and still builds; a backup only counts once this works. |
| `git fsck` | Git's own health check of its history files; "no errors" means the history is undamaged. |
| `.partial` file | A file still being written; only renamed to its real name once it has been checked. |

## Tools

| Term | Meaning |
| --- | --- |
| Emulator | A program that imitates the 2600 so its original ROM runs on a PC. |
| Stella | The best-known, very accurate Atari 2600 emulator; the project's "ruler" for what is correct. |
| Reference emulator / app | The standalone Stella 7.0 program in `F:\Ports\Tools\Stella-7.0c`, used to see and measure the original game. |
| Portable app | A program that runs from its own folder without being installed into Windows. |
| `-baseinappdir` | A Stella start-up option that keeps all its settings inside its own folder (used by `tools\run_stella.cmd`). |
| Digital signature | A maker's electronic seal on a program file; our Stella 7.0c build has none, so we compared its files with the official zip instead. |
| SmartScreen | Windows' warning when starting a program it doesn't recognise. |
| Game Properties | Stella's window (Tab → Game Properties…) showing what it knows and detects about the loaded game. |
| Auto-detect | Stella working out a setting (cartridge type, TV format) from the ROM itself instead of from its database. |
| NTSC / PAL | The US and European TV standards; NTSC draws about 60 pictures per second, PAL about 50. This ROM is NTSC. |
| Game Select / Game Reset | The console's two buttons: Select chooses the game number and players, Reset starts a new game. |
| Difficulty switches (A/B) | Two console switches, left for player 1 and right for player 2; here they change when the bonus item appears. |
| Game variation | One of the game numbers 1–8 chosen with Select; each can be for one or two players. |
| Bonus item | The small square that appears under the ghost pen at times during play. |
| Input script | A text file telling our tool which buttons and directions to press on which frames. |
| RAM byte ($80–$FF) | One of the console's 128 memory cells; the game keeps its state (position, score, settings) there. |
| AUDC / AUDF / AUDV | The TIA's three sound settings per channel: tone type (AUDC), pitch (AUDF, higher number = lower note) and volume (AUDV). |
| Sound channel | The TIA has two independent voices (0 and 1); this game uses channel 0 for everything and channel 1 only in the start tune. |
| Sample rate | How many audio values per second a sound file holds; Stella's is 31,440 Hz. |
| WAV | A plain, uncompressed audio file format any PC can play. |
| Scripted play | Joystick moves generated by our tool from a fixed recipe, so a run can be repeated exactly without a person playing. |
| Seed | The starting number of the fixed recipe; the same seed always gives the same moves. |
| Wafer | This version's name for the dots Pac-Man eats; the corner squares are the power pills. |
| CPU cycle | The smallest step of the 2600's processor; 76 of them make one scanline, 19,912 one frame. |
| Clock rate / Hz | How many cycles (or frames) happen per second; 60 Hz = 60 frames a second. |
| VSYNC / VBLANK | TIA signals: VSYNC tells the TV a new picture starts; VBLANK blacks out lines (used above and below the picture). |
| WSYNC | A TIA register; writing it makes the CPU wait until the current scanline ends, to stay in step with the beam. |
| RIOT timer (INTIM, TIM64T) | A countdown in the 2600's RIOT chip; the game sets it, does its logic, then waits until it runs out. |
| Overscan | The blank lines after the picture, before VSYNC, where games usually run logic. |
| Spare time | The part of the logic areas left unused before the timer runs out; here at least 6 lines at the top. |
| Scanline | One horizontal line of the TV picture; an NTSC 2600 frame here has 262 of them. |
| Visible window | The part of each frame's scanlines that Stella shows (here lines 23–250, 228 lines). |
| Framebuffer | The emulator's memory copy of one finished picture (160 pixels per line, one colour number each). |
| Probe (`stella_probe`) | Our measuring tool: runs the ROM in Stella's own emulator code and records every frame. |
| Colour cycling (attract) | The game slowly shifting all its colours while nobody plays (measured in C3); on Atari games this is usually done to protect the TV screen from burn-in. |
| Deterministic | Giving exactly the same result every time it is run with the same inputs. |
| Access violation | A crash where a program touched memory it may not use (Windows code 0xC0000005). |
| Phosphor effect | Stella's optional blending of each picture with the previous one, like an old TV's afterglow; it softens flicker. |
| libretro core | A version of an emulator packaged so other programs can embed it; we use Stella's own. |
| SDL3 | A library that opens windows and handles sound and game controllers on the PC. |
| Library | Ready-made code another program uses, instead of writing it from scratch. |
| Compiler | A program that turns source code (text) into a program you can run (`.exe`). |
| MSVC / `cl` | Microsoft's C++ compiler; `cl` is its command. |
| Visual Studio Build Tools | Microsoft's package that installs the compiler and build tools without the full editor. |
| Developer environment | A temporary setup started by `VsDevCmd.bat` in which `cl`, `cmake` and `ninja` can be used. |
| CMake | A tool that reads a project description (`CMakeLists.txt`) and prepares the build. |
| Ninja | A fast tool that runs the actual build steps CMake prepared. |
| C++ / C++23 | The programming language of the port; C++23 is the 2023 edition of it. |
| `/std:c++23preview` | The compiler setting that selects C++23 on this compiler (see DECISIONS T-B3-2). |
| PATH | The list of folders Windows searches when you type a command name. |
| Python | A scripting language used for small analysis helpers (standard library only). |
| PowerShell / cmd | The two Windows command-line shells used to run commands and scripts. |
| MSYS2 | A separate set of Unix-style tools already on the PC; deliberately not used by this project. |
| dasm | An assembler for 6502 code, planned for rebuilding the ROM from source (Phase F). |
| Static / shared library (`.lib` / `.dll`) | Ready-made code either built into the program (static) or kept as a separate file the program loads (shared, a DLL). |
| DLL | "Dynamic-link library": a Windows file of shared code that programs load when they start. |
| Export (`retro_*`) | A function a DLL offers to other programs; Stella's core offers 25 standard libretro ones. |
| Vendoring | Keeping an outside library's source inside our project at a fixed version, instead of downloading it at build time. |
| Source archive (`.tar.gz`, `.tar.xz`) | A compressed bundle of a project's source files, like a zip. |
| Tag | A permanent name for one exact point in a project's history, e.g. Stella's `7.0`. |
| Patch | A small, documented change to someone else's code; ours is applied to a copy at build time (T-B7-4). |
| GPL / zlib licence | Stella's licence (share the source of anything released with it) / SDL's licence (use freely, keep the notice). |
| Assembler | A tool that turns readable 6502 instructions back into a ROM file. |

## Git

| Term | Meaning |
| --- | --- |
| Git | A tool that keeps a full history of the project's files. |
| Repository | The project folder plus Git's hidden `.git` history folder. |
| Commit | One saved, named snapshot of the project you can always return to. |
| Branch / `main` | A line of history; this project uses one, called `main`. |
| `.gitignore` | The list of files Git must never save; it keeps every ROM out. |
| `.gitattributes` | Rules telling Git how to treat files, e.g. line endings and binary files. |
| Line endings (LF / CRLF) | The invisible end-of-line marks, which differ between Unix and Windows. |
| Staged | Files picked for the next commit but not yet committed. |
| Push / GitHub | Uploading the history to GitHub, a website hosting repositories; only in Phase J and only with approval. |

## Reverse engineering and testing

| Term | Meaning |
| --- | --- |
| Disassembly | Turning ROM bytes back into readable 6502 instructions. |
| Reverse engineering | Working out how a program works from the program itself, without its original source. |
| Source reconstruction | Writing readable source code that rebuilds the exact same ROM. |
| Port | The game rebuilt to run natively on another machine (here Windows), behaving like the original. |
| Trace / golden trace | A recording of what the game does frame by frame; a "golden" one is the accepted reference. |
| Lockstep test | Running the emulator and the port side by side with the same inputs and checking they agree. |
| Baseline | The recorded set of the original game's behaviours that the port must match. |
| Frame | One full TV picture; the 2600 draws 60 per second (NTSC). |

## Project words

| Term | Meaning |
| --- | --- |
| Phase / stage | The plan is split into phases A–J, each made of small stages done one per session. |
| Gate | The checklist at the end of a phase that must pass before the next phase starts. |
| D-001, D-002 … | Decisions the owner approved, in `DECISIONS.md`. |
| T-B3-2 etc. | Small technical choices Claude Code made inside a stage, also in `DECISIONS.md`. |
| Resume prompt | The standard message pasted at the start of each session. |
| `CLAUDE.md` | The rules file Claude Code reads automatically every session. |
| Preservation / modernization | Keeping the game exactly as it was / adding new features; kept separate (Rules 2–3). |
| Reference capture | A numbered picture of the original game at a known moment (title, power pill, death...), recreatable from an input script. |
| Bot | A program that plays the game for us by trying moves ahead; its moves are saved as a script, and only a replay of the script counts. |
| Host | Our own program around the game: window, sound, controls, speed. In Phase 1 the game itself is run by Stella's core. |
| Core (emulation core) | The part of Stella that pretends to be the 2600's chips. |
| Self-check | A command-line switch on our program that makes it test itself and quit, so a test can run without anyone watching. |
| SHA-1 / fingerprint | A 40-character code worked out from a file's contents. If one bit of the file changes, the code changes completely, so it proves which file it is. |
| Headless | Running without a window or any screen output; used for automatic tests. |
| Frame fingerprint | A short code worked out from one picture. If two runs give the same code for every frame, they drew identical pictures. |
| Pixel shape (aspect) | How wide a game pixel is compared with its height. The 2600's pixels are wider than tall, so the picture must be stretched sideways to look right. |
| Letterbox / pillarbox | Black bars above and below (letterbox) or at the sides (pillarbox) when the window's shape differs from the picture's. |
| Borderless fullscreen | A window with no frame that covers the whole monitor, at the desktop's own resolution. Switching is instant and the screen does not flicker, because no video mode changes. |
| Sample rate | How many sound readings per second (31,440 for this game). More readings per second means finer sound. |
| Underrun | The sound card wanted more sound than the program had ready, so it played silence: heard as a click or a gap. |
| Buffer (cushion) | A small store of sound waiting to be played, so a short hiccup in the program is not heard. Bigger is safer but adds delay. |
| Refresh rate | How many times a second the monitor redraws the screen (180 on the owner's). The game runs at 60 frames a second, so each game frame is shown for about 3 refreshes. |
| Frame pacing | Starting each game frame at the right moment so the game runs at the right speed and looks smooth. |
| Scancode | A number for a key's position on the keyboard (not the letter on it), so WASD works the same on every keyboard layout. |
| Replay | Feeding recorded inputs back into the game to check that it behaves exactly as it did when they were recorded. |
| Dead zone | The small area around the middle of a stick where a push is ignored, because a stick that is let go never rests exactly in the centre. |
| Virtual gamepad | A pretend pad made by the program itself for testing; the rest of the program treats it like a real one. |
| Latched switch | A key that flips something and leaves it there (the difficulty switches and Colour / B&W), unlike Select and Reset, which only count while the key is held. |
| Input recording | A small text file (`.inputs`) saying what the joystick and switches were doing on every frame. Played back from power-on it gives the same game again, because the game itself does nothing random. |
| GPL (GNU General Public License) | The licence of Stella. A program that contains Stella may be passed on only if its complete source code goes with it and the same licence applies. That is why the release zip holds the source. |
| Runtime files (msvcp140.dll and friends) | Small Microsoft files every program built with this compiler needs. They are shipped next to the program so the PC does not need anything installed. |
| Trace | A file with one line per frame saying what the game did on that frame: the input, the switches, a fingerprint of the picture, a fingerprint of the sound and all 128 bytes of the console's memory. Phase F compares the rebuilt game against it. |
| Baseline entry | One recorded game (an input file) with a plain-words description and a trace of what the original did. |
| Pause flag | Bit 6 of memory byte $D2. It is set while the game stops Pac-Man's own walking for a moment: the start tune, a death, a ghost eaten, and (found in Stage E3) the 84 frames after Pac-Man goes into the opening at the top or bottom of the maze. Its name is a working label. |
| Turn request | The joystick direction held while Pac-Man walks along a corridor. If it is still held when he reaches a corner he turns there; a 2-frame tap is not remembered (Stage E3). |
| Ghost place bytes | Memory bytes $B2-$B5 (x) and $B7-$BA (y) hold the four ghosts' places; found in Stage E4 by watching what moves. Working labels, not yet confirmed. |
| Score bytes | Memory bytes $CC (tens and ones) and $CE (hundreds), each half-byte one decimal digit. Working labels found in Stage E5 by matching the status bar with memory. |
| Bonus item | The small square that appears in the middle of the maze (row y = 40, x 72-80) for up to 768 frames; eating it gives 100 points. Memory byte $E7 bit 1 is set while it is on the board (working label, Stage E7). |
| Seed | A number that fixes a "random" sequence, so the same random input can be played again exactly. |
| Memory edit (poke) | Writing one value into the console's memory from outside the game, used only in two labelled test entries to reach a score that cannot be played to. Marked ARTIFICIAL; never used in play. |
| Gate E | The check at the end of Phase E that the baseline of recorded games is complete enough to be the target of the reverse-engineering phase (`docs\GATE_E.md`). |
| Disassembler | A program that turns the machine-code bytes of the ROM back into readable instructions (`LDA #$10`). |
| Assembler | The opposite: turns the readable instructions back into bytes. Disassemble then assemble must give the original bytes, or something was lost. |
| Opcode | The first byte of a 6502 instruction; it says which instruction it is and how many bytes follow. |
| Coverage map | A map of the ROM saying which bytes the processor actually ran as instructions and which it only read as data, made by running the recorded games (Stage F1). |
| Label | A name written in front of a line of the listing (`L_F123:`) so that jumps and data references can say where they go instead of using a number. |
| Scanline | One horizontal line of the TV picture. The 2600 draws 262 per frame, and the program counts its work in lines (one line = 76 processor cycles). |
| Kernel | The part of the program that draws the picture line by line, timed to the cycle, because the console has no memory for a whole picture. |
| Vertical blank / overscan | The scanlines before and after the visible picture in which the game logic runs. |
| Look-ahead read | After many instructions the processor reads the next byte without using it. The measuring tool records it, so a byte touched only that way is not data. (Stage F6) |
| Zero page | The first 256 bytes of the processor's address space. On the 2600 the chips sit in $00-$7F and the 128 bytes of memory (RAM) in $80-$FF; instructions on this page are shorter and faster. (Stage F7) |
| Stack | A part of memory where the processor keeps the return addresses of subroutine calls. Here it is $F6-$FF, growing downwards. (Stage F7) |
| Shift register (random number) | A byte whose bits are shifted along with a new bit made from two old ones; repeating this gives a long, repeatable series that looks random. (Stage F7) |
